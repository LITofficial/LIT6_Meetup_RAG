## 발표 주제

이번 발표에서는 Microsoft Learn의 [Build a copilot with Azure AI Studio - 소개](https://learn.microsoft.com/ko-kr/training/modules/build-copilot-ai-studio/1-introduction)를 바탕으로, 사용자가 가진 문서를 AI와 연결해 **근거 있는 답변을 생성하는 Copilot**을 만드는 과정을 설명합니다.

발표의 핵심은 단순합니다.

> AI를 업무에 쓰려면 모델이 얼마나 말을 잘하는지만 볼 것이 아니라, 어떤 데이터를 근거로 답변하는지를 함께 설계해야 합니다.

일반적인 생성형 AI는 자연스러운 답변을 만들 수 있습니다. 하지만 우리 조직의 내부 문서, 최신 정책, 제품 매뉴얼, 회의록, 업무 절차서까지 자동으로 알고 있지는 않습니다. 그래서 실제 업무에 적용하려면 AI가 답변하기 전에 **우리 데이터에서 필요한 정보를 찾고**, 그 정보를 바탕으로 답변하게 만드는 구조가 필요합니다.

이 발표는 그 구조를 **RAG(Retrieval-Augmented Generation)**, **Grounding**, **Azure AI Search**, **Copilot Studio**를 중심으로 풀어갑니다.

# 서론

## 1. 왜 사용자 데이터 기반 AI가 필요한가

찾고 싶은 문서가 있는데 파일명이 기억나지 않는 경험은 누구나 한 번쯤 있습니다.

회의록, 수업 자료, 회사 규정, 제품 매뉴얼처럼 자료는 분명히 어딘가에 있습니다. 내용도 대충 기억납니다. "지난주 회의에서 누가 담당하기로 했던 것 같은데", "휴가 규정 문서에 있었던 것 같은데", "장비 반납 절차가 어디엔가 있었는데" 같은 식으로 맥락은 떠오릅니다.

하지만 실제로 찾으려면 쉽지 않습니다.

- 정확한 파일명을 모르면 검색이 어렵습니다.
- 문서가 많으면 어떤 파일을 열어야 할지 모릅니다.
- PDF, 이미지, 스캔 문서처럼 검색이 잘 안 되는 자료도 있습니다.
- 자료를 찾더라도 사용자가 직접 읽고 답을 정리해야 합니다.

즉, 문제는 자료가 없는 것이 아니라 **자료를 업무 질문에 바로 연결하기 어렵다**는 데 있습니다.

## 2. 일반 LLM만으로는 왜 부족한가

이때 일반 LLM에게 질문하면 자연스럽게 답을 해줄 수 있습니다.

예를 들어 다음과 같은 질문을 할 수 있습니다.

```text
휴가 신청 절차를 알려줘.
```

```text
지난 회의에서 결정된 작업 항목을 정리해줘.
```

```text
장비 반납 규정은 어떻게 되나요?
```

하지만 일반 LLM은 우리 조직의 실제 문서를 자동으로 알고 있지 않습니다. 공개적으로 학습된 지식이나 일반적인 패턴을 바탕으로 답변할 수는 있지만, 내부 문서의 정확한 내용과 최신 변경 사항까지 보장하지는 못합니다.

| 사용자가 기대하는 것 | 일반 LLM만 사용할 때의 한계 |
| --- | --- |
| 내부 문서 기반 답변 | 모델이 해당 문서를 모를 수 있음 |
| 최신 정책 반영 | 학습 시점 이후의 변경 사항을 반영하지 못할 수 있음 |
| 출처가 있는 답변 | 어떤 문서를 근거로 답했는지 확인하기 어려움 |
| 조직별 업무 절차 안내 | 공개 데이터에 없는 조직 내부 지식은 부족함 |
| 신뢰 가능한 업무 지원 | 그럴듯하지만 실제와 다른 답변이 나올 수 있음 |

따라서 이 발표에서 다루는 문제의 핵심은 AI가 말을 못 한다는 것이 아닙니다.

> **AI가 우리 데이터를 근거로 답하고 있는지 확인하기 어렵다는 것입니다.**

## 3. 발표에서 해결하려는 문제

이번 발표에서는 다음 질문에 답하는 것을 목표로 합니다.

```text
내가 가진 문서와 데이터를 AI가 참고하게 만들려면 어떤 구조가 필요할까?
```

```text
AI가 답변할 때 실제 문서를 근거로 삼게 하려면 어떤 기술이 필요할까?
```

```text
Copilot Studio와 Azure AI Search를 사용하면 이 흐름을 어떻게 만들 수 있을까?
```

결론부터 말하면, 필요한 것은 단순한 챗봇이 아니라 **검색 가능한 지식 원본과 연결된 Copilot**입니다.

# 본론

## 1. 핵심 해결 방식: RAG와 Grounding

사용자 데이터 기반 Copilot을 이해하려면 먼저 RAG와 Grounding을 알아야 합니다.

## 1-1. RAG란 무엇인가

RAG는 **Retrieval-Augmented Generation**의 약자입니다. 한국어로는 보통 **검색 증강 생성**이라고 설명할 수 있습니다.

단어를 나누어 보면 의미가 더 명확합니다.

```text
Retrieval
  -> 질문과 관련된 정보를 먼저 검색

Augmented
  -> 검색한 정보를 모델 입력에 보강

Generation
  -> 보강된 정보를 바탕으로 답변 생성
```

즉, RAG는 모델이 혼자 기억에 의존해서 답변하는 방식이 아닙니다. 먼저 외부 지식 원본에서 관련 정보를 검색하고, 그 검색 결과를 모델에게 함께 전달한 뒤 답변을 생성하게 만드는 방식입니다.

기본 흐름은 다음과 같습니다.

```text
사용자 질문
  -> 관련 문서 검색
  -> 검색 결과를 프롬프트에 포함
  -> 언어 모델이 근거 기반 답변 생성
  -> 사용자에게 답변 반환
```

이 구조의 장점은 모델을 다시 학습시키지 않고도 새로운 문서와 최신 데이터를 답변에 활용할 수 있다는 점입니다.

## 1-2. Grounding이란 무엇인가

Grounding은 AI가 일반적인 학습 지식만으로 답하지 않고, 연결된 데이터 원본에서 찾은 실제 정보를 기반으로 답변하도록 만드는 방식입니다.

예를 들어 "휴가 신청 절차를 알려줘"라는 질문이 들어왔다고 가정해보겠습니다.

일반 LLM은 보통 다음처럼 답할 수 있습니다.

```text
휴가 신청은 보통 상급자에게 승인 요청을 하고, 회사 시스템에 신청서를 제출하면 됩니다.
```

하지만 이 답변은 일반적인 설명일 뿐입니다. 실제 우리 조직의 절차와 다를 수 있습니다.

Grounding이 적용된 Copilot은 먼저 사내 인사 규정 문서를 찾고, 그 문서에 있는 내용을 근거로 답합니다.

```text
사내 인사 규정 문서에 따르면 휴가 신청은 최소 3일 전 인사 시스템에서 신청해야 하며,
팀장 승인 후 최종 반영됩니다.
```

이 차이가 중요합니다. 업무에서 필요한 것은 단순히 자연스러운 답변이 아니라, 실제 문서에 기반한 답변입니다.

## 2. 기술 구성

이번 발표에서는 Microsoft 플랫폼을 활용해 문서 기반 Copilot 구조를 설명합니다.

| 구성 요소 | 역할 |
| --- | --- |
| Microsoft Copilot Studio | 사용자가 대화하는 Copilot 구성 |
| Azure AI Search | 문서 인덱싱 및 관련 정보 검색 |
| Azure OpenAI | 검색된 근거를 바탕으로 자연어 답변 생성 |
| Azure Blob Storage | 문서 원본 저장 |
| Microsoft AI Foundry | AI 서비스 개발과 확장을 위한 플랫폼 |

각 구성 요소는 독립적으로 존재하는 것이 아니라 하나의 흐름 안에서 연결됩니다.

```text
문서 저장
  -> 검색 가능하게 변환
  -> Copilot과 연결
  -> 질문이 들어오면 검색
  -> 검색 결과를 바탕으로 답변 생성
```

## 3. Azure Blob Storage: 문서 원본 저장

첫 번째 단계는 문서를 저장하는 것입니다.

사용자는 PDF, Word 문서, 텍스트 파일, 매뉴얼, FAQ, 회의록 같은 자료를 준비합니다. 이 자료들은 AI가 직접 답변하기 전에 참고해야 할 원본 데이터입니다.

Azure Blob Storage는 이런 문서 원본을 저장하는 역할을 합니다.

여기서 중요한 점은 Blob Storage에 문서를 올리는 것만으로 AI가 문서를 이해하는 것은 아니라는 점입니다. 이 단계의 문서는 아직 "쌓여 있는 자료"에 가깝습니다.

```text
PDF
Word 문서
회의록
업무 매뉴얼
FAQ
  -> Blob Storage에 저장
```

저장된 문서를 실제로 검색하고 활용하려면 다음 단계에서 Azure AI Search가 필요합니다.

## 4. Azure AI Search: 문서를 검색 가능한 지식으로 만들기

Azure AI Search는 문서를 검색 가능한 형태로 변환하고, 사용자의 질문과 관련된 정보를 찾아주는 역할을 합니다.

일반 검색은 보통 파일명이나 정확한 키워드에 의존합니다. 하지만 업무 문서 검색에서는 사용자가 항상 정확한 단어를 입력하지 않습니다. "휴가", "연차", "쉬는 날", "근태 신청"처럼 서로 다른 표현으로 같은 의도를 말할 수 있습니다.

Azure AI Search는 이런 상황에서 문서의 내용을 인덱싱하고, 질문과 관련된 문서를 찾는 검색 계층이 됩니다.

## 4-1. 데이터 원본

먼저 검색 대상이 되는 데이터 원본이 필요합니다.

```text
Blob Storage
Database
PDF
DOCX
TXT
스캔 문서
이미지 문서
```

이 단계의 데이터는 사람이 보면 이해할 수 있지만, 시스템 입장에서는 아직 검색하기 좋은 구조가 아닐 수 있습니다. 특히 PDF나 이미지 기반 문서는 텍스트 추출이 필요할 수 있습니다.

## 4-2. 인덱싱

인덱싱은 문서를 검색하기 좋은 형태로 정리하는 과정입니다.

Azure AI Search는 문서 안의 내용을 분석하고, 검색 가능한 필드로 정리합니다. 문서 제목, 본문, 메타데이터, 작성일, 카테고리 같은 정보를 검색 인덱스에 저장할 수 있습니다.

```text
문서 원본
  -> 내용 추출
  -> 필드 정리
  -> 검색 인덱스 생성
```

인덱스가 만들어지면 사용자의 질문이 들어왔을 때 전체 문서를 처음부터 읽는 것이 아니라, 검색 인덱스를 기반으로 빠르게 관련 정보를 찾을 수 있습니다.

## 4-3. AI 보강과 의미 기반 검색

Azure AI Search는 단순 키워드 검색을 넘어 AI 보강 기능과 의미 기반 검색을 함께 활용할 수 있습니다.

예를 들어 다음과 같은 작업이 가능합니다.

- 문서 안의 텍스트 추출
- 스캔 문서나 이미지 속 글자 OCR
- 핵심 키워드 추출
- 문서 분류
- 의미적으로 유사한 문서 검색

이 기능을 활용하면 사용자가 정확한 파일명이나 정확한 문장 표현을 몰라도 관련 문서를 찾을 수 있습니다.

| 일반 검색 | Azure AI Search 기반 검색 |
| --- | --- |
| 정확한 키워드 중심 | 질문 의도와 문맥 기반 검색 가능 |
| 파일명 검색에 의존 | 문서 내용 기반 검색 가능 |
| 사용자가 직접 문서 확인 | Copilot 답변의 근거로 활용 가능 |

## 5. Copilot Studio: 사용자와 만나는 AI 에이전트 구성

Copilot Studio는 사용자가 실제로 질문하고 답변받는 Copilot을 구성하는 도구입니다.

개발자가 모든 대화 UI와 흐름을 직접 구현하지 않아도, Copilot Studio에서 에이전트를 만들고 지식 원본을 연결할 수 있습니다.

이번 발표에서 Copilot Studio의 역할은 다음과 같습니다.

- 사용자가 질문을 입력하는 대화형 인터페이스 제공
- Azure AI Search 같은 지식 원본 연결
- 질문이 들어왔을 때 관련 문서를 참조하도록 구성
- 답변 스타일과 동작 방식 설정
- 필요한 경우 배포 채널과 연결

즉, Copilot Studio는 검색과 LLM을 사용자 경험으로 연결하는 계층입니다.

## 6. Azure OpenAI: 검색된 근거로 답변 생성

Azure OpenAI는 검색된 문서 내용을 바탕으로 자연어 답변을 생성합니다.

여기서 중요한 점은 Azure OpenAI가 혼자 답을 만들어내는 것이 아니라, Azure AI Search가 찾은 관련 문서 조각을 함께 받아 답변한다는 점입니다.

질문 처리 흐름은 다음과 같습니다.

```text
사용자 질문
  -> Copilot Studio가 질문 처리
  -> Azure AI Search에서 관련 문서 검색
  -> 검색 결과를 프롬프트에 포함
  -> Azure OpenAI가 답변 생성
  -> Copilot이 사용자에게 응답
```

이 방식은 일반 LLM 답변보다 업무 적용에 더 적합합니다. 모델이 "그럴듯한 답"을 만드는 데 그치지 않고, 실제 문서에서 찾은 내용을 기반으로 답변할 수 있기 때문입니다.

## 7. 전체 아키텍처 흐름

전체 구조를 하나로 정리하면 다음과 같습니다.

```text
[사용자 문서]
  PDF / DOCX / 회의록 / 매뉴얼 / FAQ
        |
        v
[Azure Blob Storage]
  문서 원본 저장
        |
        v
[Azure AI Search]
  문서 분석, 인덱싱, 검색
        |
        v
[Copilot Studio]
  지식 원본 연결, 대화 흐름 구성
        |
        v
[사용자 질문]
  자연어 질문 입력
        |
        v
[검색 + 생성]
  관련 문서 검색
  검색 결과를 프롬프트에 포함
  Azure OpenAI 답변 생성
        |
        v
[Grounded Response]
  문서 근거 기반 답변 제공
```

이 구조에서 핵심은 모델이 모든 문서를 외우고 있다고 가정하지 않는다는 것입니다.

문서는 별도의 지식 원본으로 관리하고, 질문이 들어올 때마다 관련 내용을 검색해 답변에 활용합니다.

## 8. 일반 검색과 RAG Copilot의 차이

일반 검색과 RAG Copilot은 비슷해 보일 수 있지만 사용 경험은 다릅니다.

| 구분 | 일반 검색 | RAG 기반 Copilot |
| --- | --- | --- |
| 입력 방식 | 키워드 중심 | 자연어 질문 |
| 결과 형태 | 문서 목록 | 문서 기반 답변 |
| 문맥 이해 | 제한적 | 질문 의도 기반 검색 가능 |
| 답변 생성 | 사용자가 직접 문서를 읽어야 함 | AI가 문서를 바탕으로 요약 및 설명 |
| 활용 목적 | 파일 찾기 | 업무 질문 답변 |

일반 검색은 "어떤 문서를 봐야 하는지"를 알려주는 데 가깝습니다.

RAG Copilot은 "그 문서에 따르면 답이 무엇인지"까지 도와주는 방향에 가깝습니다.

예를 들어 일반 검색에서는 "휴가 신청"을 검색한 뒤 여러 문서를 직접 열어봐야 합니다. RAG Copilot에서는 "휴가 신청 절차를 알려줘"라고 질문하면 관련 문서를 찾고, 그 내용을 바탕으로 절차를 정리해줄 수 있습니다.

## 9. 데모 시나리오

이번 데모의 목표는 단순히 AI가 답변하는 모습을 보여주는 것이 아닙니다.

> 사용자가 올린 문서를 AI가 검색하고, 그 검색 결과를 근거로 답변하는 흐름을 확인하는 것입니다.

데모 흐름은 다음과 같습니다.

```text
1. 사용자가 업무 문서나 매뉴얼을 준비한다.
2. 문서를 Blob Storage에 업로드한다.
3. Azure AI Search가 문서를 검색 가능한 형태로 인덱싱한다.
4. Copilot Studio에서 지식 원본을 연결한다.
5. 사용자가 자연어로 질문한다.
6. Copilot이 관련 문서를 찾는다.
7. 검색된 내용을 바탕으로 답변한다.
8. 사용자는 문서 기반 답변을 확인한다.
```

## 9-1. 예시 질문

```text
휴가 신청 절차를 알려줘.
```

```text
장비 반납 규정은 어떻게 되나요?
```

```text
신입 구성원이 먼저 확인해야 할 문서는 무엇인가요?
```

```text
회의록에서 지난주에 결정된 작업 항목을 정리해줘.
```

## 9-2. 데모에서 보여줄 핵심 포인트

데모에서 강조해야 할 부분은 다음과 같습니다.

- AI가 단순히 일반 지식으로 답하지 않는다는 점
- 사용자가 제공한 문서가 검색 대상이 된다는 점
- 질문과 관련된 문서를 먼저 찾는다는 점
- 검색 결과가 답변 생성의 근거로 사용된다는 점
- 문서가 바뀌면 답변도 최신 문서 기준으로 개선될 수 있다는 점

## 10. 기대 효과

이 구조를 적용하면 다음과 같은 효과를 기대할 수 있습니다.

## 10-1. 업무 효율 향상

- 문서 검색 시간을 줄일 수 있습니다.
- 정확한 파일명을 몰라도 자연어로 질문할 수 있습니다.
- 반복적인 문서 문의를 줄일 수 있습니다.
- 사용자가 문서를 처음부터 끝까지 읽지 않아도 핵심 답변을 얻을 수 있습니다.

## 10-2. 답변 신뢰도 향상

- AI 답변이 내부 문서나 업무 자료를 근거로 생성됩니다.
- 일반적인 추측성 답변을 줄일 수 있습니다.
- 최신 문서를 지식 원본으로 연결하면 답변의 최신성도 높일 수 있습니다.
- 출처 표시를 함께 설계하면 검증 가능한 답변 경험을 만들 수 있습니다.

## 10-3. 조직 지식 활용 확대

- 흩어져 있던 문서를 검색 가능한 지식 자산으로 바꿀 수 있습니다.
- 사내 규정, FAQ, 매뉴얼, 교육 자료를 Copilot과 연결할 수 있습니다.
- 신규 구성원 온보딩, 고객 상담, 내부 업무 지원 등에 확장할 수 있습니다.

## 11. 한계와 고려할 점

RAG를 적용한다고 해서 모든 문제가 자동으로 해결되는 것은 아닙니다. 실제 서비스로 운영하려면 다음 요소를 함께 고려해야 합니다.

## 11-1. 데이터 품질

AI가 좋은 답변을 하려면 연결된 문서의 품질이 좋아야 합니다. 문서가 오래되었거나, 서로 모순되거나, 정리가 되어 있지 않다면 답변 품질도 떨어질 수 있습니다.

## 11-2. 검색 품질

RAG의 성능은 검색 품질에 크게 의존합니다. 관련 문서를 잘못 찾으면 모델이 아무리 좋아도 답변 품질이 낮아집니다.

따라서 인덱스 구조, 검색 필드, 문서 분할 방식, 의미 검색 설정 등을 계속 조정해야 합니다.

## 11-3. 권한 관리

모든 사용자가 모든 문서를 볼 수 있으면 안 됩니다. 실제 업무 환경에서는 사용자 권한에 따라 접근 가능한 문서가 달라야 합니다.

예를 들어 인사 문서, 재무 문서, 고객 정보가 포함된 문서는 접근 제어가 반드시 필요합니다.

## 11-4. 출처 표시

업무용 AI에서는 "답변"만큼이나 "근거"가 중요합니다. 사용자는 AI가 어떤 문서를 참고했는지 확인할 수 있어야 합니다.

따라서 답변에 출처 문서나 참고한 문단을 함께 보여주는 방식이 필요합니다.

## 11-5. 운영 모니터링

실제 서비스에서는 다음 요소를 지속적으로 확인해야 합니다.

- 사용자가 어떤 질문을 많이 하는지
- 검색 실패가 자주 발생하는 질문은 무엇인지
- 답변이 부정확하다는 피드백이 있는지
- 어떤 문서가 자주 참조되는지
- 최신 문서가 정상적으로 인덱싱되는지

중요한 것은 기술을 연결하는 것 자체가 아니라, 어떤 데이터를 연결할지, 검색 품질을 어떻게 관리할지, 답변 근거를 어떻게 검증할지입니다.

# 결론

생성형 AI는 자연스러운 답변을 만들 수 있습니다. 하지만 실제 업무에서 중요한 것은 답변이 자연스러운가만이 아닙니다.

> **그 답변이 어떤 근거에서 나왔는지가 더 중요합니다.**

이번 발표에서 다루는 Grounded RAG Copilot은 사용자가 가진 문서와 AI를 연결해, 단순한 챗봇을 업무 지식 기반 에이전트로 확장하는 방법을 보여줍니다.

결국 핵심은 AI에게 모든 것을 외우게 만드는 것이 아닙니다.

**현실의 문서와 데이터를 검색 가능한 지식으로 만들고, 그 지식을 AI의 답변 과정에 연결하는 것입니다.**

이 관점으로 보면 AI 서비스 설계의 출발점은 거대한 모델을 만드는 것이 아니라, 우리가 이미 가진 데이터 중 어떤 것을 AI가 참고하게 만들 것인지 정하는 데 있습니다.

## 발표의 최종 메시지

이번 발표를 한 문장으로 정리하면 다음과 같습니다.

> Copilot의 가치는 모델 자체가 아니라, 사용자의 데이터와 연결될 때 커집니다.

사용자 문서를 Blob Storage에 저장하고, Azure AI Search로 검색 가능한 지식으로 만들고, Copilot Studio에서 대화형 에이전트로 연결하면, AI는 단순한 대화 도구를 넘어 실제 업무를 도와주는 지식 기반 시스템이 될 수 있습니다.
